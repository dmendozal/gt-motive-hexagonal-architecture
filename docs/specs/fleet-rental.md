# Fleet Rental Specification

## Purpose

Implement a fleet rental microservice for a renting company. The service exposes REST endpoints to create fleet vehicles, list available vehicles, rent a vehicle, and return a rented vehicle.

This document is the source of truth for implementation and tests. Changes to behavior must be reflected here before code changes.

## Architecture Expectations

Follow the repository's hexagonal architecture conventions:

- Domain rules live in `Domain`.
- Use cases live in `ApplicationCore`.
- MVC controllers, requests, responses, and presenters live in `Api`.
- Persistence adapters live in `Infrastructure`.
- Host configuration and wiring live in `Host`.

The core must not depend on web, MongoDB, Docker, or framework-specific details. Use ports for persistence and clock access.

New HTTP features must be implemented with controllers and presenters, matching the base solution design. Expected business failures use `DomainException` and are translated to HTTP by the API exception filter.

## Vocabulary

- **Vehicle**: A fleet asset that can be rented.
- **Person**: A customer or user who rents vehicles.
- **Rental**: The active or completed assignment of one vehicle to one person.
- **Available vehicle**: A vehicle that is not currently rented.
- **Active rental**: A rental that has not been returned.

## Data Model

### Vehicle

- `id`: unique entity identifier, generated by the system.
- `vin`: required, unique vehicle identifier.
- `brand`: required.
- `model`: required.
- `manufacturingDate`: required.
- `status`: `Available` or `Rented`.

### Person

- `id`: unique entity identifier, generated by the system.
- `documentId`: required, unique person document identifier. It can represent DNI, NIF, or equivalent.
- `name`: required.

### Rental

- `id`: unique entity identifier, generated by the system.
- `vehicleId`: required.
- `personDocumentId`: required.
- `personName`: required.
- `rentedAt`: required UTC timestamp.
- `returnedAt`: optional UTC timestamp.
- `status`: `Active` or `Returned`.

## Business Rules

- A vehicle must have a required, unique `vin`.
- A person must have a required, unique `documentId`.
- A vehicle cannot be created when its `manufacturingDate` is older than five years from the current UTC date.
- The five-year rule is inclusive: if today is `2026-06-07`, `2021-06-07` is valid and `2021-06-06` is invalid.
- Only available vehicles can be rented.
- A person cannot have more than one active rental at the same time.
- Renting a vehicle marks it as `Rented`.
- Returning a rental marks the rental as `Returned` and the vehicle as `Available`.
- Returning a missing, already returned, or unrelated rental must fail with a clear error.

## Time Handling

Use a clock port, for example `IClock` or `IDateTimeProvider`, instead of calling `DateTime.UtcNow` directly. Business rules use the current UTC date.

## Persistence

Support MongoDB and in-memory persistence through adapters. The host selects the provider explicitly through `Infrastructure:Provider`; it does not infer persistence from the environment name. The domain and application layers must depend only on repository/unit-of-work ports. The service must be runnable locally without external dependencies; in-memory persistence is acceptable for local execution and automated specs.
Mongo adapters should enforce the main uniqueness invariants with indexes, especially unique `vin` for vehicles and one active rental per `personDocumentId`.

## REST API

### Create Vehicle

`POST /vehicles`

Request:

```json
{
  "vin": "VIN-001",
  "brand": "Toyota",
  "model": "Corolla",
  "manufacturingDate": "2023-01-10"
}
```

Success: `201 Created`

### List Available Vehicles

`GET /vehicles/available`

Success: `200 OK`

### Rent Vehicle

`POST /rentals`

Request:

```json
{
  "vehicleId": "vehicle-id",
  "personDocumentId": "12345678A",
  "personName": "Jane Doe"
}
```

Success: `201 Created`

### Return Rental

`POST /rentals/{rentalId}/return`

Request:

```json
{
  "personDocumentId": "12345678A"
}
```

Success: `200 OK`

## Error Messages

- `VehicleNotFound`: `Vehicle was not found.`
- `VehicleAlreadyRented`: `Vehicle is not available for rent.`
- `PersonAlreadyHasActiveRental`: `Person already has an active rental.`
- `RentalNotFound`: `Rental was not found.`
- `RentalAlreadyReturned`: `Rental has already been returned.`
- `RentalDoesNotBelongToPerson`: `Rental does not belong to the specified person.`
- `VehicleTooOld`: `Vehicle manufacturing date exceeds 5 years.`
- `DuplicateVehicle`: `Vehicle already exists.`
- `DuplicatePerson`: `Person already exists.`

## Acceptance Criteria

### Create a valid vehicle

Given today is `2026-06-07`  
When a vehicle with VIN `VIN-001` and manufacturing date `2023-01-10` is created  
Then the vehicle is added to the fleet  
And the vehicle status is `Available`

### Reject an old vehicle

Given today is `2026-06-07`  
When a vehicle with manufacturing date `2021-06-06` is created  
Then creation is rejected with `VehicleTooOld`

### Reject a duplicated VIN

Given a vehicle with VIN `VIN-001` exists  
When another vehicle with VIN `VIN-001` is created  
Then creation is rejected with `DuplicateVehicle`

### List available vehicles

Given one available vehicle exists  
And one rented vehicle exists  
When available vehicles are requested  
Then only the available vehicle is returned

### Rent an available vehicle

Given an available vehicle exists  
And person `12345678A` has no active rentals  
When person `12345678A` rents the vehicle  
Then a rental is created with status `Active`  
And the vehicle status becomes `Rented`

### Reject renting an unavailable vehicle

Given a rented vehicle exists  
When another person tries to rent that vehicle  
Then the rental is rejected with `VehicleAlreadyRented`

### Reject a second active rental for the same person

Given person `12345678A` already has an active rental  
When person `12345678A` tries to rent another available vehicle  
Then the rental is rejected with `PersonAlreadyHasActiveRental`

### Return a rented vehicle

Given person `12345678A` has an active rental for vehicle `VIN-001`  
When person `12345678A` returns the rental  
Then the rental status becomes `Returned`  
And the vehicle status becomes `Available`

### Reject returning a missing rental

Given no rental exists with id `missing-rental-id`  
When a return is requested for `missing-rental-id`  
Then the return is rejected with `RentalNotFound`

### Reject returning an already returned rental

Given a returned rental exists  
When a return is requested again  
Then the return is rejected with `RentalAlreadyReturned`

### Reject returning another person's rental

Given person `12345678A` has an active rental  
When person `87654321B` tries to return that rental  
Then the return is rejected with `RentalDoesNotBelongToPerson`

## Test Mapping

- **Unit test**: validate that a person cannot have more than one active rental.
- **Functional test**: execute the real HTTP host against MongoDB through Testcontainers.
- **Infrastructure test**: validate one REST method at host level, including request reception and model validation.

## Docker Requirement

The host project must remain runnable outside Docker and inside Docker. Docker support should use official .NET images and include the required Visual Studio profile/configuration so Docker can be selected as startup option.
